# Optional control plane integration (contract 1)

SF Manager is optional. Execution, authorization, journals and delegation stay in
the target repository. A manager must never execute code or schemas fetched from
a target repository.

Read `installation-contract.json` and `schemas/config.schema.json` at the exact
40-character SF commit. The contract is generated by `npm run contract` through
the same renderer and create-only planner as `scripts/install.ts`. It contains
versioned files for all manager/test, coding, config-only and deployment variants.
The only substitution is `__SF_FACTORY_COMMIT__`, replaced with that exact SHA.
Harness pins are already resolved from `runtime.json`; never substitute a newer
Harness independently. Deployment defaults are checks/Test, production, /opt/app;
edit the generated YAML/config explicitly if different values are needed.

Preserve existing files on install. Updates require a comparison of installed
files against their *old* contract; locally modified workflows need manual review.
Configuration migrations are not automatically safe (see `migrations`). Absence
of a contract at an old release is a blocked operation, not permission to use main.
Release version is `factoryVersion`; GitHub Release tags must be resolved through
annotated tags to immutable commits. Drafts and prereleases are never automatic
updates. A release must include this file, schema, templates and runtime.json.

`factory.enabled` remains authoritative. Installation may activate on merge.
Secret provisioning is independent and requires explicit repository authorization.

Dispatch `factory-manager.yml` with mode=manager and dry_run=true. Its pinned SF
Action writes the artifact `sf-sanity-RUN_ID-ATTEMPT`, containing `sf-sanity.json`:
formatVersion=1, mutationFree=true, passed (boolean), outcome, run/attempt and
correlationId. A disabled factory produces passed=false. Missing/invalid artifacts
or failed workflows are not successful checks. A passed check exercises read and
planning paths only; it explicitly does not verify production side effects.
Bootstrap, notifications, merges, worker publication, dispatch and deployment are
guarded in mutation-free mode. No issue/journal is written by a dry-run manager.
The only writes are local reports and the workflow's diagnostic artifact.

Correlation already exists: manager journal correlationId=RUN_ID-ATTEMPT, worker
run-name=`Factory worker EXECUTION_ID`, and versioned journal intent/result
envelopes record executionId and issueNumber. Consumers must not infer links from
timestamps. Configuration schema is generated from runtime Zod input, including
defaults and enums; there is no second manually maintained schema.
