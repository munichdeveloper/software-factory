# Recorded Backofficer RC evidence

The accepted runtime/package source is commit `1d7ac107c2a1ca67e1a45f6daa1ad6f0cd97d3e0`. Later commits add documentation only. `backofficer-canary-evidence.json` consolidates the runtime, independent checks, repository review, CI, cleanup and first unaccepted attempt. `release.json` records the unpublished draft and read-back-verified asset hashes.

The JSON files in Git use LF. Uploaded release assets retain their original exported bytes; the asset SHA256 values in `release.json` and the release SHA256SUMS apply to those exact downloads. A checksum difference caused by newline normalization does not change the recorded values, but must not be described as the same byte hash.

`collector.mjs.txt` and `collector.py` record the actual external acceptance collectors, not installed product entrypoints. Their original workspace layout was `work/temporal-migration/backofficer-rc-runner.mjs`, `backofficer-rc.py`, and `software-factory/` checked out at the accepted runtime commit. The Python collector mounts the JavaScript collector at `/app/rc-runner.mjs` in the freshly built image. The image is built from operations/temporal-runtime/Dockerfile with the exact FACTORY_SHA. Credentials and the approved issue/branch setup arrive through bounded stdin, not tracked files. The child broker receives repository-scoped App authority; the actual worker receives only its separate role token and Temporal/broker addresses. The model runs separately on GitHub with contents-read permissions.

Reproduction requires explicit authorization for a fresh test issue, branch and model costs, the expected existing GitHub App installation, and an exact review of the setup values. Do not reuse the completed issue or blindly replay effects from the deleted test database. No production deployment or merge is part of this procedure.
